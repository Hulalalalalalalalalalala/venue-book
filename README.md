# roottrace

roottrace 计算数据批次的 Merkle 根值，用于比较两个批次的内容是否一致。

## 构建

```sh
cargo build --offline
```

## 测试

```sh
cargo test --offline
```

除单元测试（SHA-256 向量、记录划分、MTH 递归构造、包含证明逐位置验证）外，
`tests/root_regression.rs` 通过实际构建出的命令做端到端回归：以事先固定的完整
根值校验 7、8、9 条记录（跨过 8 条这一二次幂边界）三个共享前七条记录的固定批次，
并覆盖重复内容改一个位置、交换两条不同记录、遗漏空记录、重复纳入一条记录、
末尾 LF 有无等价，以及空文件与单个 LF 的区别；同时校验成功输出恰为一行 64 位
小写十六进制加换行、退出状态为 0、stderr 无失败信息，并保留 `--version`、
参数错误（退出 2）和读取失败（退出 1）的既有行为。

`tests/prove_regression.rs` 对 `roottrace prove` 做同样的端到端保障：固定证明
向量（9 条非二次幂批次的首条、重复内容位置和末条，8 条平衡批次中部，含 NUL/
CR/非 UTF-8 字节的 10 条长短混合批次中的长记录，以及单个 LF 的空路径）逐字节
校验输出的一行 JSON；证明中的 `root` 与 `root` 命令对同一文件的结果一致；
相同内容位于不同位置得到不同证明；末尾 LF 有无两种文件形式给出逐字节相同的
证明；序号越界（含空文件）退出 1 且标准输出为空；负数、非数字、超过 64 位
无符号整数范围、缺少或多余参数退出 2 并输出用法说明；读取失败退出 1 且不输出
残缺证明。

`tests/long_record_regression.rs` 对**长记录**做同样的端到端保障：记录去掉 LF
分隔符后为 54、55、56、63、64、65 字节（叶子哈希输入 `0x00 || 记录` 相应为
55–57 与 64–66 字节，贴近或跨过 SHA-256 的 56 字节填充边界与 64 字节分块边界）
以及一条 135 字节（>128，叶子输入进入第三个分块）的记录，各自作为单条记录
构成批次时都必须匹配固定根值；每条长记录内部都含 NUL、CR 与非 UTF-8 字节且
以非文本字节结尾，覆盖内容在内部和末尾的字节保真。两条长记录（65 与 135
字节）各有仅改动末尾一个字节的变体，根值必须对应修改后的完整记录——只处理
记录前面部分的实现无法通过。另设一个由长短记录共同组成的 10 条固定批次
（RFC 6962 的 k=8 切分使长记录同时落在左右子树），并同样校验该批次末尾字节
变体，确认长记录在批次中与单条记录时遵守同一标准。所有长记录批次都同时以
"末尾有/无结束用 LF"两种文件形式校验，二者表示同一记录序列、根值相同。

预期根值不来自被检查的功能：`tests/reference/rfc6962_vectors.py` 是独立的 Python
参考实现（标准库 `hashlib.sha256`，递归定义与栈折叠两种算法互验），运行后可
重新生成各固定记录序列（含上述全部长记录与长短混合批次）对应的根值常量供核对。
该脚本对包含证明同样提供两种结构不同的算法（RFC 6962 第 2.1.1 节 PATH 的递归
定义，以及自根向叶下降、兄弟子树哈希改用栈折叠计算的写法），二者在每个固定序列
的每个位置上结果一致，再用独立的递归包含验证器把每条证明重新哈希回批次根值；
脚本末尾输出供 `tests/prove_regression.rs` 使用的固定证明常量。

## 用法

```sh
roottrace root <文件路径>            # 计算批次根值
roottrace prove <文件路径> <记录序号>  # 生成指定记录在整个批次中的成员证明
roottrace --version                  # 打印版本号
```

### `roottrace root <文件路径>`

读取文件中的全部记录，按 RFC 6962 第 2.1 节的 SHA-256 Merkle Tree Hash
计算根值，向标准输出写出一行 64 个小写十六进制字符（行末带换行），退出状态为 0：

```text
b137985ff484fb600db93107c77b0365c80d78f5b429ded0fd97361d077999eb
```

两个文件的根值相同，说明它们的记录序列完全相同；根值不同则内容有差异。

**记录如何划分：** 文件按原始字节读取，以 LF（`\n`，0x0a）分隔记录，分隔符
本身不属于记录。记录中的空格、制表符、CR（`\r`）以及非 UTF-8 字节都属于
记录内容，原样参与计算。文件换行方式会影响根值：使用 CRLF 换行的文件，每条
记录末尾会多出一个 `\r` 字节，与对应 LF 换行的文件根值不同。

**非 UTF-8 文件路径：** 在 Unix 等允许文件名字节不是合法 UTF-8 的系统上，
路径按用户在命令行传入的原始字节原样访问，无需重命名或额外指定编码；相对
路径与绝对路径同样适用。因此路径中出现例如 0xff 字节时，程序不会在读取
文件前异常退出，也不会误读同目录下仅因显示替换字符“�”而看起来同名的另一个
文件。两个文件内容相同而路径字节不同，根值与证明完全相同。路径不存在、
指向目录或读取失败（即使路径本身含非 UTF-8 字节）时仍按下面的规则退出 1。
命令名与记录序号必须是合法 UTF-8 文本；其中出现非 UTF-8 字节按用法错误
退出 2。

**空文件与空记录的区别：**

- 空文件（0 字节）表示零条记录，根值是空输入的 SHA-256
  （`e3b0c442...b7852b855`）。
- 只含一个 LF 的文件表示一条空记录，与空文件的根值不同。
- 连续的 LF 会产生空记录，例如 `a\n\n` 是 `a` 和一条空记录。
- 末尾的 LF 只结束最后一条记录，不额外产生空记录，因此 `a\nb` 与 `a\nb\n`
  的根值相同。

重复内容不会被去重或合并：相同字节出现在不同位置仍是不同的记录，记录顺序
也参与计算。

**错误处理：**

- 缺少文件路径、参数多余或命令未知：向标准错误输出用法说明，退出状态为 2。
- 文件不存在、路径是目录或读取失败：向标准错误输出失败原因，退出状态为 1，
  标准输出不会写出任何根值。

### `roottrace prove <文件路径> <记录序号>`

为指定记录生成它在**整个批次**中的 RFC 6962 第 2.1.1 节包含证明（成员证明）。
记录划分规则与 `root` 完全一致（LF 分隔、末尾 LF 不增加记录、空记录占独立
位置、CR/NUL/非 UTF-8 字节原样保留）。

**记录序号（第二个参数）：** 从 0 开始的十进制非负整数，只接受 ASCII 数字，
按文件中的记录顺序定位：`0` 是第一条记录，`1` 是第二条，以此类推。相同内容
出现在多个位置时，证明的是序号指定的那个位置，不会去重，也不会自动改成第一
次出现的位置。序号等于或大于实际记录数时，该位置不存在。例如只含一个 LF 的
文件有一条记录，只能对序号 `0` 生成证明；真正的空文件（0 字节）没有任何可选
记录，对任何序号都报位置不存在。

成功时标准输出恰为一行 JSON 对象（行末带换行），退出状态为 0，标准错误为空：

```sh
$ printf 'a\nb\nc' > batch.txt
$ roottrace prove batch.txt 1
{"tree_size":3,"leaf_index":1,"root":"36642e73c2540ab121e3a6bf9545b0a24982cd830eb13d3cd19de3ce6c021ec1","audit_path":["022a6979e6dab7aa5ae4c3e5e45f7e977112a7e63593820dbec1ec738a24f93c","597fcb31282d34654c200d3418fca5705c648ebf326ec73d8ddef11841f876d8"]}
```

字段含义：

- `tree_size`：JSON 整数，完整批次的记录数。
- `leaf_index`：JSON 整数，被证明记录的序号（即命令行给出的位置）。
- `root`：64 位小写十六进制字符串，与 `roottrace root` 对同一文件输出的
  根值完全相同。
- `audit_path`：字符串数组，每个元素是 64 位小写十六进制哈希，按**从叶子向根**
  的顺序排列（RFC 6962 第 2.1.1 节的成员证明定义）。批次只有一条记录时为空
  数组 `[]`；记录数不是二次幂时按 RFC 的不均匀子树构造证明，既不复制末尾
  记录也不补空记录（例如 9 条记录时最后一条的证明只有一个哈希，即前 8 条
  子树的 MTH）。

证明中**不包含**原始记录：接收方用目标记录的原始字节、`leaf_index`、
`tree_size` 和 `audit_path` 重新哈希并与 `root` 比对，即可核对该记录确实位于
该位置。

**错误处理：**

- 位置不存在（空文件，或序号达到/超过实际记录数）：向标准错误说明该位置
  不存在，退出状态为 1，标准输出为空。
- 序号不是由 ASCII 数字组成的十进制非负整数（负数、非数字、超出 64 位无符号
  整数范围等），或缺少、多余参数：向标准错误输出用法说明，退出状态为 2。
- 文件不存在、路径是目录或读取失败：向标准错误输出失败原因，退出状态为 1，
  标准输出不会写出残缺证明。
