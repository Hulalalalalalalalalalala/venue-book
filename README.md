# roottrace

roottrace 计算数据批次的 Merkle 根值，用于比较两个批次的内容是否一致。

## 构建

```sh
cargo build --offline
```

## 测试

```sh
cargo test --offline
```

除单元测试（SHA-256 向量、记录划分、MTH 递归构造、成员证明递归构造与
RFC 6962 第 2.1.2 节独立验证器、序号解析）外，`tests/root_regression.rs`
通过实际构建出的命令做端到端回归：以事先固定的完整根值校验 7、8、9 条记录
（跨过 8 条这一二次幂边界）三个共享前七条记录的固定批次，并覆盖重复内容改一个
位置、交换两条不同记录、遗漏空记录、重复纳入一条记录、末尾 LF 有无等价，以及
空文件与单个 LF 的区别；同时校验成功输出恰为一行 64 位小写十六进制加换行、
退出状态为 0、stderr 无失败信息，并保留 `--version`、参数错误（退出 2）和
读取失败（退出 1）的既有行为。

`tests/prove_regression.rs` 对 `roottrace prove` 做同样的端到端保障：以
独立 Python 参考实现事先固定的 audit path 常量校验 B9 批次 0、1、4、7、8
号位置（含与 0 号字节相同的 4 号重复记录、以及作为完整右子树因而路径只有
一个哈希的 8 号位置），校验 JSON 中根值与 `root` 命令对同一文件的输出逐字符
相同、`tree_size`/`leaf_index` 为整数、路径哈希为 64 位小写十六进制、
单条记录路径为空数组且不回显原始记录；并覆盖位置不存在（退出 1、stderr 说明、
stdout 为空）、空文件无可选位置、序号格式错误与参数数量错误（退出 2、用法说明）、
读取失败（退出 1、无残缺证明）。

`tests/long_record_regression.rs` 对**长记录**做同样的端到端保障：记录去掉 LF
分隔符后为 54、55、56、63、64、65 字节（叶子哈希输入 `0x00 || 记录` 相应为
55–57 与 64–66 字节，贴近或跨过 SHA-256 的 56 字节填充边界与 64 字节分块边界）
以及一条 135 字节（>128，叶子输入进入第三个分块）的记录，各自作为单条记录
构成批次时都必须匹配固定根值；每条长记录内部都含 NUL、CR 与非 UTF-8 字节且
以非文本字节结尾，覆盖内容在内部和末尾的字节保真。两条长记录（65 与 135
字节）各有仅改动末尾一个字节的变体，根值必须对应修改后的完整记录——只处理
记录前面部分的实现无法通过。另设一个由长短记录共同组成的 10 条固定批次
（RFC 6962 的 k=8 切分使长记录同时落在左右子树），并同样校验该批次末尾字节
变体，确认长记录在批次中与单条记录时遵守同一标准。所有长记录批次都同时以
"末尾有/无结束用 LF"两种文件形式校验，二者表示同一记录序列、根值相同。

预期根值不来自被检查的功能：`tests/reference/rfc6962_vectors.py` 是独立的 Python
参考实现（标准库 `hashlib.sha256`，递归定义与栈折叠两种算法互验），运行后可
重新生成各固定记录序列（含上述全部长记录与长短混合批次）对应的根值常量供核对；
其中还包含 RFC 6962 第 2.1.1 节成员路径（audit path）的直接转写与第 2.1.2 节
迭代验证算法，运行时会对每个固定批次的每个位置自洽校验 PATH 与验证算法一致，
并重新生成 `tests/prove_regression.rs` 使用的固定路径常量。

## 用法

```sh
roottrace root <文件路径>                 # 计算批次根值
roottrace prove <文件路径> <记录序号>     # 生成指定位置记录的成员证明
roottrace --version                       # 打印版本号
```

记录序号是从 0 开始的十进制非负整数（只接受 ASCII 数字），按文件中的记录
顺序定位：文件 `a\nb\nc\n` 中 `a`、`b`、`c` 的序号分别为 0、1、2。

### `roottrace prove <文件路径> <记录序号>`

为**指定位置**的记录生成其在整个批次中的 RFC 6962 第 2.1.1 节成员证明
（inclusion proof / audit path）。证明只按序号定位：相同内容出现在多个位置
时，每个位置有各自的证明，不会去重，也不会自动改选第一次出现的位置。

成功时向标准输出写出**一行** JSON 对象（行末带换行），退出状态为 0，
标准错误为空：

```sh
$ roottrace prove batch.txt 1
```

```json
{"tree_size":9,"leaf_index":1,"root":"a8a3e76ecf28b850e84cb5465729921212ffd07de3c0e6e170cd233bf723adc3","audit_path":["2a158d8afd48e3f88cb4195dfdb2a9e4817d95fa57fd34440d93f9aae5c4f82b","ac96b46d1760957393e22a8a365d54e58645a244550bc3c566892cdbdc5d8fc1","416649c1a4f116151112df7d7d3faa85d5d8c60699e153e7a3c57a1abab7a242","5cc496b84d9250622d5de1219d1f156e7973503fbd80f7f3364800bbfa2947d2"]}
```

各字段：

- `tree_size`：JSON 整数，完整批次的记录总数。
- `leaf_index`：JSON 整数，被证明记录的序号（即命令行给定的序号）。
- `root`：整个批次的根值，64 位小写十六进制，与 `roottrace root` 对同一
  文件的输出完全相同。
- `audit_path`：字符串数组，每个元素是 64 位小写十六进制哈希，**从叶子向根**
  排列，定义见 RFC 6962 第 2.1.1 节。接收方用目标记录的**原始字节**配合
  `leaf_index`、`tree_size` 与该路径，按第 2.1.2 节即可核对记录的位置并重建
  根值。证明本身**不包含原始记录**。

记录数不是二次幂时不复制末尾记录、不补空记录：RFC 6962 的非平衡切分
天然会让某些位置（例如 9 条记录批次中的第 8 号）得到更短的路径。整个批次
只有一条记录时，`audit_path` 为空数组 `[]`，`tree_size`、`leaf_index` 与
`root` 仍正常输出。只含一个 LF 的文件可以为序号 0 生成证明（该记录为空）；
真正的空文件没有任何可选记录。

**记录划分**与 `root` 完全相同：LF 只作分隔符，末尾 LF 不额外增加记录，
空记录占据独立位置，CR、NUL 与非 UTF-8 字节原样参与计算。

**错误处理：**

- 序号达到或超过实际记录数（包括空文件上的任何序号）：向标准错误说明该
  位置不存在，退出状态为 1，标准输出为空。
- 序号不是 ASCII 十进制非负整数（负数、非数字、含空格或小数点等），或超过
  64 位无符号整数范围（大于 `18446744073709551615`）：输出用法说明，
  退出状态为 2。
- 缺少或多余参数、命令未知：输出用法说明，退出状态为 2。
- 文件不存在、路径是目录或读取失败：向标准错误输出失败原因，退出状态为 1，
  标准输出不会写出残缺证明。

### `roottrace root <文件路径>`

读取文件中的全部记录，按 RFC 6962 第 2.1 节的 SHA-256 Merkle Tree Hash
计算根值，向标准输出写出一行 64 个小写十六进制字符（行末带换行），退出状态为 0：

```text
b137985ff484fb600db93107c77b0365c80d78f5b429ded0fd97361d077999eb
```

两个文件的根值相同，说明它们的记录序列完全相同；根值不同则内容有差异。

**记录如何划分：** 文件按原始字节读取，以 LF（`\n`，0x0a）分隔记录，分隔符
本身不属于记录。记录中的空格、制表符、CR（`\r`）以及非 UTF-8 字节都属于
记录内容，原样参与计算。文件换行方式会影响根值：使用 CRLF 换行的文件，每条
记录末尾会多出一个 `\r` 字节，与对应 LF 换行的文件根值不同。

**空文件与空记录的区别：**

- 空文件（0 字节）表示零条记录，根值是空输入的 SHA-256
  （`e3b0c442...b7852b855`）。
- 只含一个 LF 的文件表示一条空记录，与空文件的根值不同。
- 连续的 LF 会产生空记录，例如 `a\n\n` 是 `a` 和一条空记录。
- 末尾的 LF 只结束最后一条记录，不额外产生空记录，因此 `a\nb` 与 `a\nb\n`
  的根值相同。

重复内容不会被去重或合并：相同字节出现在不同位置仍是不同的记录，记录顺序
也参与计算。

**错误处理：**

- 缺少文件路径、参数多余或命令未知：向标准错误输出用法说明，退出状态为 2。
- 文件不存在、路径是目录或读取失败：向标准错误输出失败原因，退出状态为 1，
  标准输出不会写出任何根值。
